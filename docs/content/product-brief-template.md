# Product brief template

> Fill one copy per product (e.g. `docs/content/briefs/<product-slug>.md`). Short bullet answers are fine.
> This gives us enough to write the product page, choose keywords and plan the industry page.

## Basics
- **Product name:**
- **One-line description:** (what it does, for whom)
- **Industry / industries:**
- **Status:** live with paying clients / pilot / in development
- **Website URL slug (suggested):** `/products/...`

## Buyer
- **Who buys it:** (job titles, company type and size)
- **Who uses it day to day:**
- **The problem it solves:** (what they do today without it, and what that costs them)
- **Main competitors or alternatives:** (other products, manual work, Excel, in-house teams)

## Product
- **Key features:** (3–6)
- **How it works:** (3–5 steps)
- **Inputs and outputs:** (what goes in, what comes out)
- **Integrations / delivery:** (API, webhook, exports, ERP, etc.)
- **Deployment:** SaaS / dedicated / on-premise / private cloud
- **Security and compliance:** (only what is true today)

## Proof
- **Clients we can name:** (with permission) and logos
- **Results with numbers:** (time saved, accuracy, volume, cost)
- **Case study available?** yes / no / can be written
- **Testimonial available?**

## Commercials
- **Pricing model:** per document / per user / licence / project
- **Can we show indicative INR pricing?**
- **Entry offer:** demo / free trial / paid pilot / sample run

## Search
- **What would a buyer type into Google to find this?** (list 5–10 phrases, in the buyer's words)
